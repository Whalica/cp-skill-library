# 题目难度与 Idea 质量评分 Skill v5

## 1. 目标

本 Skill 用于在不直接依赖官方 rating 的前提下，对算法竞赛题目进行结构化评价。v5 同时评价“题有多难”和“题本身是否有质量、是否值得学习”，两套体系彼此独立。

输出包括：

1. **CF 估分**
   - 整份评价的第一视觉中心。
   - 由公共难度映射得到，不受 Idea 质量影响。

2. **公共难度**
   - 题目在标准竞赛环境下，对普通竞赛群体的平均赛时 AC 难度。
   - 用于估算题目大致对应的 CF rating 档位。

3. **Idea 质量**
   - 评价题目是否有意思、核心思路是否漂亮、能否学到可迁移的东西、多个知识点是否形成自然完整的结构。
   - 独立使用 0.0~10.0 分与等级制。
   - **不得参与公共难度、目标体感或 CF rating 的数值计算。**

4. **目标人群体感难度**
   - 指定水平与能力画像的选手，在赛时面对该题时的实际负担。
   - 允许目标人群在某些专题明显强于或弱于公共群体。

5. **赛时波动**
   - 描述不同选手、不同场次之间体感差异的离散程度。
   - 赛时波动不直接计入最终分，只影响估分区间与置信度。

6. **估分置信度**
   - 描述当前估分结论的可靠程度。
   - 受题面完整度、解法确定性、数据强弱、题型冷门程度等因素影响。

核心原则：

```text
CF 估分是主要输出
公共难度 ≠ 目标人群体感难度
Idea 质量 ≠ 难度
Idea 质量不得抬高或压低 CF 估分
难度中心 ≠ 赛时波动
赛时波动不直接加分
目标人群不得重复校准
展示顺序 ≠ 内部计算顺序
```

---

## 2. 标准竞赛环境

公共难度必须基于统一环境评价，否则不同题目的分数不可比较。

默认环境：

```yaml
standard_context:
  platform_style: "Codeforces 风格综合竞赛"
  contest_duration: "2 小时 15 分钟"
  language: "C++17"
  participant_profile: "持续参加 rated contest 的普通竞赛选手"
  editorial_access: false
  external_search: false
  local_template_allowed: true
  subtasks: false
  interactive: false
  statement_quality: "正常"
  sample_quality: "正常"
  pretest_strength: "正常"
  system_test_strength: "正常"
  time_limit_pressure: "正常"
  memory_limit_pressure: "正常"
```

若题目实际环境不同，必须在“环境修正”中说明，例如：

- 结果填空；
- 输出答案；
- 部分分；
- 交互；
- 通信；
- 开放数据；
- 极弱 pretest；
- 极强卡常；
- 非 C++ 主场；
- 允许长时间离线计算。

- CF 估分始终是总评中的主要视觉元素。

## 4. 评分范围

所有基础维度均固定纳入，分数为：

```text
0.0 ~ 10.0
```

保留一位小数。

| 分数 | 含义 |
|---:|---|
| 0.0 | 该维度几乎没有负担 |
| 2.0 | 较低负担 |
| 4.0 | 中等偏低 |
| 5.0 | 中等 |
| 6.0 | 中等偏高 |
| 8.0 | 较高 |
| 10.0 | 极高 |

重要规则：

```text
某维度不存在时记 0.0，不允许“不纳入”。
```

这样可以避免“增加一个简单门槛反而使平均分下降”的数学问题。

# 5. 基础评价维度

基础维度共七项，权重固定，总和为 1.00。

| 维度 | 权重 |
|---|---:|
| 题意理解与形式化 | 0.10 |
| 前置知识门槛 | 0.15 |
| 核心观察与结论发现 | 0.20 |
| 算法设计与复杂度优化 | 0.20 |
| 正确性论证与反例排除 | 0.10 |
| 实现、调试与性能工程 | 0.15 |
| 错路诱导与解法路径宽度 | 0.10 |

公共难度与目标人群体感分别对这七项评分。

---

## 5.1 题意理解与形式化

评价从自然语言题面转化为明确数学对象、状态或操作模型的难度。

包括：

- 题面是否长、绕、翻译质量差；
- 操作时序是否复杂；
- 是否需要识别等价模型；
- 是否难以确定真正需要优化的量；
- 环、树、集合、偏序、博弈等抽象是否自然。

| 分数 | 特征 |
|---:|---|
| 0~2 | 题意直接，模型几乎显然 |
| 3~5 | 需要整理状态或做一层抽象 |
| 6~8 | 题意与算法对象差异较大，建模是主要门槛 |
| 9~10 | 题意高度复杂，形式化本身接近解题主体 |

边界：

- 不评价关键结论是否难发现；
- 不评价从模型到高效算法的优化过程；
- 只评价“题面到底在做什么，以及如何精确定义它”。

---

## 5.2 前置知识门槛

评价解决该题所需知识的稀有度、熟悉度和记忆要求。

需要区分：

```text
知识是否少见
```

与：

```text
掌握知识后，应用是否困难
```

前者属于本维度，后者属于算法设计或观察。

| 分数 | 特征 |
|---:|---|
| 0~2 | 基础语法、排序、前缀和、简单枚举 |
| 3~5 | 二分、基础图论、普通 DP、并查集、Fenwick、常见数论 |
| 6~8 | 线段树复杂维护、字符串算法、网络流、树上博弈、Burnside、冷门结论 |
| 9~10 | 极冷门专题、高级图论、高级代数或强依赖专门知识 |

注意：

- 常见模板代码长，不代表知识稀有度高。
- 公式极短但普通选手几乎没见过，也可能得高分。
- 存在合理无模板解时，应按最容易赛时到达的路径评分。

---

## 5.3 核心观察与结论发现

评价关键性质、构造、规律或突破口在赛时被自然发现的难度。

重点是发现路径，而不是结论表述看起来是否陌生。

必须进行“防后见之明检查”：

1. 不知道正解时，最自然的第一步是什么？
2. 普通选手为什么会观察这个量？
3. 普通随机小数据是否能暴露规律？
4. 是否必须先猜中观察对象，才能看出结论？
5. 反例是否容易构造？
6. 样例是否真实提供了方向，而非事后牵强解释？

| 分数 | 特征 |
|---:|---|
| 0~2 | 题面几乎直接给出，或自然推一步即可 |
| 3~5 | 手推、画图、枚举小数据后较自然 |
| 6~8 | 需要针对性推导，普通尝试不容易发现 |
| 9~10 | 单点结论极隐蔽，缺少可达发现路径 |

短代码不等于观察简单。

---

## 5.4 算法设计与复杂度优化

评价从正确性质或模型出发，设计出满足约束的算法有多难。

包括：

- 从暴力到目标复杂度的优化；
- 状态设计；
- 状态压缩；
- 数据结构中维护什么信息；
- 离线、分治、扫描线、摊还、增量维护；
- 去掉一个复杂度维度；
- 时间复杂度和空间复杂度的达成；
- 多个算法模块的组合。

| 分数 | 特征 |
|---:|---|
| 0~2 | 观察得到后直接实现即可 |
| 3~5 | 一到两层常规状态设计或复杂度优化 |
| 6~8 | 需要非显然状态、降维或多模块组合 |
| 9~10 | 算法结构深，复杂度达成路径极窄 |

该维度沿用 v4 的设计，用于避免“知道模板”和“会设计算法”被混为一谈。

---

## 5.5 正确性论证与反例排除

评价选手能否在赛时确认方案正确，而不仅仅是猜到一个看起来合理的做法。

包括：

- 贪心交换论证；
- 必要性与充分性；
- 单调性证明；
- 状态转移完整性；
- 构造是否覆盖全部情况；
- 是否存在隐蔽反例；
- 是否容易获得提交信心。

| 分数 | 特征 |
|---:|---|
| 0~2 | 正确性几乎显然 |
| 3~5 | 常规归纳、交换或不变量证明 |
| 6~8 | 猜法容易但证明困难，反例不易排除 |
| 9~10 | 结论高度反直觉，严格证明接近题目主体 |

注意：

- “能写暴力对拍”只能降低验证风险，不能替代数学证明难度。
- 某题可猜对但难以放心提交，本维度应提高。

---

## 5.6 实现、调试与性能工程

同时评价逻辑实现和工程约束。

建议内部拆分：

```text
逻辑实现与边界
性能与资源工程
```

考虑：

- 代码量；
- 状态数量；
- 分类讨论；
- 下标与边界；
- 溢出与取模；
- 多测清空；
- 递归栈；
- 内存布局；
- cache；
- 卡常；
- 语言差异；
- debug 成本；
- 构造输出验证；
- 交互协议。

| 分数 | 特征 |
|---:|---|
| 0~2 | 简单循环或少量判断 |
| 3~5 | 普通实现，有少量边界 |
| 6~8 | 长代码、状态多、性能压力明显 |
| 9~10 | 大模拟、复杂几何、交互、通信或极端工程题 |

强制规则：

- 实现分 `>= 7.0` 时，公共最终分通常不应低于 `5.5`。
- 实现分 `>= 8.0` 且边界密集时，公共最终分通常不应低于 `6.0`。
- 强选手可以降低体感，但不能把长实现风险直接降为 0。

---

## 5.7 错路诱导与解法路径宽度

评价题目是否容易把选手引向错误方向，以及正确路径是否过窄。

包括：

- 假贪心；
- 假单调性；
- 状态爆炸的错误 DP；
- 误用高级数据结构；
- 弱样例导致伪规律；
- 多个看似合理但错误的方向；
- 正解是否只有一条狭窄路径；
- 错误方向能否快速证伪。

| 分数 | 特征 |
|---:|---|
| 0~2 | 正确方向自然，错路少 |
| 3~5 | 有一些常见误区 |
| 6~8 | 错路多，排错成本高 |
| 9~10 | 正解反直觉且路径极窄 |

注意：

- 本维度不重复计算“核心观察本身有多难”。
- 只评价搜索空间、错误反馈和路径宽度。

---

# 6. Idea 质量评价

Idea 质量用于回答：

```text
这题有没有意思？
核心思路本身质量如何？
做完能不能学到可迁移的东西？
多个知识点是否形成自然、完整的结构？
```

Idea 质量与难度完全独立：

```text
高难度题可以 Idea 很差
低难度题可以 Idea 很好
知识点很多不代表 Idea 好
只有一个观察也可以拿高分
冷门结论不等于新鲜或有价值
```

## 6.1 Idea 维度与权重

| 维度 | 权重 |
|---|---:|
| 新鲜感与趣味性 | 0.25 |
| 核心 Idea 质量 | 0.25 |
| 学习与迁移价值 | 0.30 |
| 知识融合与结构完整性 | 0.20 |

Idea 综合分：

\[
I=0.25I_1+0.25I_2+0.30I_3+0.20I_4
\]

保留一位小数。

---

## 6.2 新鲜感与趣味性

评价题目是否具有探索感、设计辨识度和非机械性。

| 分数 | 特征 |
|---:|---|
| 0~2 | 纯模板、机械计算，几乎没有设计感 |
| 3~5 | 常规题，有一些变化但整体熟悉 |
| 6~8 | 有明显特色，推导过程存在探索感 |
| 9~10 | 设计鲜明，题目本身就值得研究 |

注意：

- 冷门不等于有趣；
- 包装新奇不等于 Idea 新鲜；
- 仅仅把常规模板换背景，不应提高本项。

---

## 6.3 核心 Idea 质量

评价真正决定解法的关键观察、转化、构造或统一视角本身是否简洁、自然、有解释力。

| 分数 | 特征 |
|---:|---|
| 0~2 | 基本没有核心 Idea，主要依赖实现或模板 |
| 3~5 | 常见套路或局部技巧 |
| 6~8 | 转化漂亮，能够揭示题目真正结构 |
| 9~10 | 极强统一视角，结论简洁且具有明显深度 |

评价重点不是“这个 Idea 多难想到”。

- “难想到”主要属于难度体系中的核心观察；
- “想到以后是否漂亮、统一、解释力强”属于 Idea 质量。

因此一个极难猜但非常生硬的特殊结论，不应仅因难猜而得到高 Idea 分。

---

## 6.4 学习与迁移价值

这是 Idea 体系中权重最高的维度。

评价做完这题以后，选手是否真正增加了一种以后还能使用的思维工具。

包括：

- 新的建模方式；
- 常见对象之间的等价转化；
- 贡献重构；
- 状态空间压缩；
- 从局部关系转成整体结构；
- min/max 对偶视角；
- 枚举对象的改变；
- 可复用的证明方式；
- 可迁移的数据结构维护设计。

| 分数 | 特征 |
|---:|---|
| 0~2 | 做完主要只是记住本题 |
| 3~5 | 能巩固一个算法或常用技巧 |
| 6~8 | 能学到一种可复用的观察或转化方式 |
| 9~10 | 能明显改变以后处理一类问题的思考方式 |

不得因为“知识点本身高级”自动给高分。

---

## 6.5 知识融合与结构完整性

评价多个步骤、算法或知识点是否形成自然依赖关系，整个解法是否结构完整。

| 分数 | 特征 |
|---:|---|
| 0~2 | 明显拼板子，步骤之间缺少内在联系 |
| 3~5 | 一个主算法配若干常规辅助工具 |
| 6~8 | 多个知识点存在自然依赖，组合合理 |
| 9~10 | 各部分高度统一，缺一不可，整体像一个完整结构 |

强制规则：

```text
多知识点 ≠ 高质量
单一知识点 ≠ 低质量
融合质量 > 知识点数量
```

例如“线段树 + KMP + 网络流”若只是机械串联，不应因为用了三个专题就得高分。

---

## 6.6 Idea 等级

| Idea 分 | 等级 | 含义 |
|---:|:---:|---|
| 9.0~10.0 | S | 极优秀，值得专门收藏 |
| 8.0~8.9 | A | 很好的题，明显值得做 |
| 7.0~7.9 | B+ | 有不错的设计或学习价值 |
| 6.0~6.9 | B | 合格且有一定收获 |
| 5.0~5.9 | C+ | 普通 |
| 4.0~4.9 | C | 比较平庸 |
| <4.0 | D | Idea 质量较弱 |

展示时统一使用：

```text
8.4 / 10（A）
```

数值与等级统一使用括号连接，不使用特殊居中点号或其他兼容性不稳定的分隔符。

---

## 6.7 Idea 评价边界

为避免与难度体系重复计费：

- 难不难想到：计入“核心观察与结论发现”；
- Idea 漂不漂亮：计入“核心 Idea 质量”；
- 知识冷不冷门：计入“前置知识门槛”；
- 学完以后是否可迁移：计入“学习与迁移价值”；
- 多模块组合本身难不难设计：计入“算法设计”；
- 多模块组合是否自然、完整：计入“知识融合与结构完整性”。

Idea 分只用于评价题目质量、推荐程度与复盘价值，绝不进入 CF rating 映射。

# 7. 基础分计算

公共基础分：

\[
B_{\text{public}}=\sum_i w_i s_i
\]

目标人群基础体感：

\[
B_{\text{target}}=\sum_i w_i t_i
\]

其中：

- \(s_i\) 为公共维度分；
- \(t_i\) 为目标人群维度分；
- 所有维度固定纳入；
- 权重总和为 1。

禁止：

- 删除低分维度；
- 先对目标人群逐项降分，再通过 rating gap 二次降分；
- 因为结果“看起来不对”而随意调整某个项目。

---

# 8. 瓶颈与组合效应

简单平均可能掩盖不可绕过的高门槛，因此必须应用以下规则。

## 8.1 单点门槛下限

若存在不可绕过的核心门槛 \(M\)，则公共最终分通常不低于：

\[
M-0.5
\]

适用条件：

- 没有合理替代解法；
- 该门槛不只是实现细节；
- 不通过该门槛基本无法推进。

目标人群是否应用取决于其是否已掌握该门槛。

---

## 8.2 多个独立门槛

如果存在多个彼此独立的难点，不应只取平均。

定义高门槛为基础维度中：

\[
s_i\ge6.0
\]

且难点来源彼此独立。

| 独立高门槛数量 | 组合修正 |
|---:|---:|
| 0~1 | 0 |
| 2 | \(+0.2\sim+0.4\) |
| 3 | 累计 \(+0.5\sim+0.8\) |
| 4 或更多 | 根据具体结构说明，通常 \(+0.8\sim+1.2\) |

禁止把同一个观察拆成“建模、结论、转化”三个门槛重复计算。

---

## 8.3 短代码观察题约束

若同时满足：

- 前置知识门槛低；
- 算法设计简单；
- 实现短；
- 边界少；
- 核心规律可通过自然小数据发现；
- 错路不强；

则公共最终分通常不应超过：

\[
4.5
\]

若观察极其明显，可限制在：

\[
3.5\sim4.0
\]

如果结论难以自然发现，则不适用该上限。

---

## 8.4 实现题下限

若主思路常规但实现复杂度高：

- 实现分 `>= 7.0`：公共最终分通常不低于 `5.5`；
- 实现分 `>= 8.0` 且边界密集：公共最终分通常不低于 `6.0`。

---

# 9. 环境修正

v5 仍只允许对基础结构之外的赛时环境进行修正。

最终分：

\[
F=\operatorname{clamp}(B+C,0,10)
\]

其中 \(C\) 为环境修正总和。

普通题的环境修正建议控制在：

\[
-1.0\sim+1.0
\]

超过此范围必须说明其特殊性。

---

## 9.1 约束提示强度

| 情况 | 修正 |
|---|---:|
| 约束强烈提示唯一复杂度方向 | \(-0.3\sim-0.6\) |
| 有一定提示 | \(-0.1\sim-0.3\) |
| 无明显提示 | 0 |
| 约束具有迷惑性 | \(+0.2\sim+0.5\) |

---

## 9.2 官方样例提示

| 情况 | 修正 |
|---|---:|
| 样例直接暴露关键规律 | \(-0.2\sim-0.5\) |
| 覆盖主要边界 | \(-0.1\sim-0.2\) |
| 普通 | 0 |
| 样例弱或误导 | \(+0.1\sim+0.4\) |

不能因为知道正解后能解释样例，就认定样例有强提示。

---

## 9.3 题面表达质量

| 情况 | 修正 |
|---|---:|
| 题面特别清晰，定义严谨 | \(-0.1\sim-0.2\) |
| 正常 | 0 |
| 翻译差、定义歧义、示例不足 | \(+0.2\sim+0.6\) |

---

## 9.4 数据、pretest 与 hack 风险

必须区分：

- 理论正解难度；
- 赛时通过难度。

| 情况 | 修正 |
|---|---:|
| 数据明显弱，假做法可过 | 赛时通过难度下调 |
| pretest 弱、system test 强 | 不下调理论难度，说明赛时风险 |
| 数据强，卡边界充分 | 实现风险可小幅上调 |
| 数据未知 | 不修正 |

---

## 9.5 提交形式

| 类型 | 影响 |
|---|---|
| 普通在线编程 | 基准 |
| 结果填空 | 可允许慢程序与多重校验，通常下调实现和复杂度压力 |
| 输出答案 | 强调构造与验证，可能大幅改变难度 |
| 部分分 | 需要额外评价得分路径 |
| 交互 | 增加协议、信息获取和实现风险 |
| 通信 | 通常显著提高建模与实现负担 |
| 开放数据 | 需要考虑数据分析和特化策略 |

提交形式既可影响基础维度，也可产生环境修正。

---

## 9.6 时间、内存与语言限制

| 情况 | 修正 |
|---|---:|
| 时空非常宽松 | \(-0.1\sim-0.3\) |
| 正常 | 0 |
| 明显卡常或卡内存 | \(+0.2\sim+0.6\) |
| 特定语言显著不利 | 单独说明 |

如果性能优化本身是算法主体，应计入基础维度，而不是只作为修正。

---

# 10. 目标人群体感计算

目标人群体感必须通过七个维度重新评分。

例如一个树上博弈题：

- 公共前置知识门槛可能为 7.0；
- 若目标人群熟悉 SG，则目标前置知识门槛可降到 2.0；
- 若其实现能力一般，实现分不一定下降。

最终体感：

\[
F_{\text{target}}=\operatorname{clamp}\left(\sum_i w_i t_i+C_{\text{target}},0,10\right)
\]

rating gap 仅作检查：

```text
若目标人群 rating 远高于公共估分，但体感仍很高，
应检查是否存在冷门知识、长实现、几何、交互或专项短板。
```

禁止：

```text
逐项评分后，再按照 gap 机械减分。
```

---

# 11. CF 估分映射

v3 的线性公式：

\[
800+200F
\]

最大只能得到 2800，无法覆盖 2900～3500+，因此继续使用 v4 引入的分段锚点映射。

## 11.1 锚点

| 最终分 \(F\) | CF 等价 rating |
|---:|---:|
| 0.0 | 800 |
| 1.0 | 1000 |
| 2.0 | 1200 |
| 3.0 | 1400 |
| 4.0 | 1600 |
| 5.0 | 1800 |
| 6.0 | 2000 |
| 7.0 | 2300 |
| 8.0 | 2600 |
| 9.0 | 3000 |
| 10.0 | 3500+ |

相邻锚点之间线性插值。

例如：

- \(F=4.5\Rightarrow1700\)
- \(F=6.5\Rightarrow2150\)
- \(F=7.5\Rightarrow2450\)
- \(F=8.5\Rightarrow2800\)
- \(F=9.5\Rightarrow3250\)

该映射是初始经验模型，后续应通过历史锚点题校准。

---

## 11.2 档位化

合法档位：

```text
800, 900, 1000, ..., 3500, 3500+
```

规则：

1. 连续估分 `< 850`：800；
2. `[850,3450)`：四舍五入到最近整百；
3. `[3450,3550)`：3500；
4. `>=3550`：3500+。

---

# 12. 赛时波动

赛时波动描述不同选手和不同场次之间体感的离散程度，不直接进入总分。

| 等级 | 特征 |
|---|---|
| 低 | 难度主要来自稳定可训练内容，选手表现集中 |
| 中 | 有一定观察或知识命中差异 |
| 高 | 单点观察、专题知识或路径狭窄导致明显分化 |
| 极高 | 想到即秒、想不到坐牢，且错误反馈很弱 |

波动来源可包括：

- 专题知识命中；
- 单点结论；
- 正解路径宽度；
- 错路反馈；
- 样例提示；
- 实现稳定性；
- 数据强弱。

重要规则：

```text
波动不加分。
导致波动的客观结构，已经分别计入基础维度。
```

---

# 13. 估分区间与置信度

## 13.1 波动对区间宽度的影响

| 赛时波动 | rating 区间宽度 |
|---|---|
| 低 | 中心值上下约 100 |
| 中 | 上下约 100~200 |
| 高 | 上下约 200~300 |
| 极高 | 上下约 300 或更大 |

区间端点必须落在合法 CF 档位。

---

## 13.2 估分置信度

| 置信度 | 条件 |
|---|---|
| 高 | 题面完整、正解明确、题型常见、数据环境已知 |
| 中 | 有一定观察或知识波动，但总体结构清晰 |
| 低 | 冷门专题、可能存在更简单解、数据未知或题面不完整 |

需要降低置信度的情况：

- 只看到一种复杂解法；
- 不确定是否存在民间简单解；
- 数据强弱未知；
- 官方题面缺失；
- 冷门 OJ 或特殊赛制；
- 题目高度依赖平台生态。

# 15. 主导难点与训练价值

## 15.1 主导难点

必须指出一到三个真正主导难度的因素，例如：

- 核心观察；
- 算法设计；
- 前置知识；
- 复杂度优化；
- 正确性证明；
- 实现工程；
- 错路排除。

不能机械重复所有维度。

## 15.2 训练价值

训练价值必须与 Idea 质量分析联动，不能只写泛化标签。至少回答以下问题：

1. **最值得学习的观察是什么？**
2. **它可以迁移到什么类型的问题？**
3. **最终使用的算法 / 数据结构是核心，还是只是实现工具？**
4. **是否值得加入复盘、专题题单或收藏？**
5. **Idea 的主要缺点是什么？**

可训练内容例如：

- 状态设计；
- 复杂度降维；
- 构造；
- 贪心交换；
- 反例构造；
- 数据结构维护信息设计；
- 树形 DP；
- 博弈建模；
- 自动机计数；
- 性能工程；
- 题意形式化；
- 贡献重构；
- 枚举对象改变；
- 等价类 / 连通块转化；
- 只在特殊状态集合上 DP。

推荐程度应结合 Idea 质量和训练价值，而不是难度：

```text
值得重点复盘
值得做
可做可不做
主要用于模板练习
Idea 较弱，不建议作为重点训练题
```

# 16. 输出格式与总评视觉规则

## 16.1 输出前先完成全部评分

**内部计算顺序和最终展示顺序必须分离。**

在输出任何正式评价正文前，必须先完成：

- 七维公共难度评分；
- 七维目标人群体感评分；
- 瓶颈与组合修正；
- 环境修正；
- 公共最终分；
- 目标人群体感；
- CF 连续估分与档位化；
- 合理 rating 区间；
- 赛时波动；
- 估分置信度；
- Idea 四维评分、综合分与等级；
- 一句话总评。

完成以上计算后，才开始正式输出。

禁止：

```text
边分析边输出，直到全文末尾才第一次出现公共难度或 Idea 质量
先给维度表，再在最后补总评
因为计算过程靠后，就把核心结论也放到靠后位置
```

---

## 16.2 总评必须位于最前

正式输出的第一个主体部分必须是“总评”。

视觉优先级固定为：

```text
CF 估分 > 公共难度 ≈ Idea 质量 > 合理区间 / 目标体感 / 波动 / 置信度
```

其中 **CF 估分是绝对主要信息**。

### 推荐视觉结构

```markdown
# 题目评价

## 总评

$$
\boxed{
\begin{array}{c}
\textbf{CF 估分}\\[3pt]
\mathbf{xxxx}
\end{array}
}
$$

$$
\boxed{\textbf{公共难度：}\ x.x/10}
\qquad
\boxed{\textbf{Idea 质量：}\ x.x/10\ \textbf{（A）}}
$$

| CF 合理区间 | 目标人群体感 | 赛时波动 | 估分置信度 |
|:---:|:---:|:---:|:---:|
| **xxxx～xxxx** | **x.x / 10** | **高** | **中** |

> **一句话总评：** ...
```

规则：

1. CF 估分使用独立的大方框，且字号 / 布局明显强于其他结论。
2. 公共难度与 Idea 质量使用第二层方框，可以并排展示。
3. Idea 等级统一写成 `8.4 / 10（A）` 形式。
4. 数值与等级使用括号表达，不使用特殊居中点号作为视觉分隔符。
5. 总评中不展开计算过程。
6. 总评必须在任何维度评分表之前出现。
7. 结尾允许再次给“最终摘要”，但它只是复述，不能代替开头总评。

## 16.3 正文推荐顺序

总评之后，正文按以下顺序展开：

1. 难度构成；
2. Idea 质量；
3. 核心 Idea / 解法结构；
4. 瓶颈与组合效应；
5. 环境修正；
6. 难度类型拆分；
7. 主导难点与赛时波动；
8. 训练价值；
9. 可选最终摘要。

不要求每题都机械展开所有标题；简单题可以适当压缩，但总评字段不能缺失。

# 17. 评分流程

严格按以下顺序进行内部计算：

1. 阅读完整题面、约束、提交形式和样例；
2. 确认赛时合理可想到的最简单正解；
3. 写出发现路径，进行防后见之明检查；
4. 分别评价七个公共难度维度；
5. 根据目标画像分别评价七个目标维度；
6. 检查难度维度是否重复计费；
7. 应用单点门槛和独立多门槛规则；
8. 只对外部赛时环境进行修正；
9. 得到公共最终分和目标体感；
10. 使用分段锚点映射 CF rating；
11. 根据赛时波动确定合理区间；
12. 给出估分置信度；
13. 独立评价 Idea 四个维度；
14. 计算 Idea 综合分并确定等级；
15. 提炼核心 Idea、迁移价值、推荐程度和一句话总评；
16. **完成以上所有内部计算后，才开始正式输出；**
17. 正式输出第一部分必须是完整“总评”，其中 CF 估分为第一视觉中心；
18. 再展开难度、Idea、训练价值等分析；
19. 最后才与官方 rating 对照；
20. 如需最终摘要，只能复述已有结论，不新增关键分析。

---

# 18. 模型校准规则

单题评分时不得用官方 rating 反推答案。

但模型开发阶段可以使用历史题进行离线校准。

推荐流程：

1. 每个 200 分段选择若干锚点题；
2. 覆盖数学、DP、图论、数据结构、字符串、构造、实现、交互；
3. 多名评价者独立盲评；
4. 记录维度分、最终分、官方 rating、通过率、解题时间；
5. 统计平均绝对误差、中位绝对误差、题型偏差和评价者间方差；
6. 调整权重和映射锚点；
7. 不对单题强行拟合官方 rating。

Idea 体系校准时，应优先比较多名评价者对“是否值得做、能否迁移、结构是否自然”的一致性，而不是拿官方 rating 作为参照。

---

# 19. 注意事项

1. 不使用当前题目的官方 rating 作为评分依据。
2. 官方 rating 只能用于事后对照或模型离线校准。
3. CF 估分是总评的第一视觉中心。
4. 正式输出前必须先完成全部评分计算。
5. 总评必须位于正文最前，不得等分析结束后才首次给出公共难度或 Idea 质量。
6. 所有难度基础维度固定纳入，不存在则记 0。
7. 公共难度与目标人群体感必须同时给出。
8. 目标人群按维度重新评分，不得再用 rating gap 二次校准。
9. Idea 质量独立于难度，不得参与公共难度、目标体感和 CF rating 计算。
10. Idea 质量固定评价四项：新鲜感与趣味性、核心 Idea 质量、学习与迁移价值、知识融合与结构完整性。
11. 多知识点不等于高 Idea 质量；单一核心观察也可以得到高 Idea 分。
12. 冷门知识不等于新鲜、有趣或有学习价值。
13. Idea 等级使用 S、A、B+、B、C+、C、D。
14. Idea 展示统一使用 `x.x / 10（等级）`，不使用特殊居中点号分隔。
15. 赛时波动不直接参与总分。
16. rating 区间应随波动变化。
17. 必须输出估分置信度。
18. 核心观察、形式化和算法设计不得重复计费。
19. “难不难想到”与“Idea 漂不漂亮”必须分开评价。
20. 复杂度优化必须单独评价。
21. 猜到但难以确认正确的题，应提高“正确性论证”分。
22. 冷门知识应提高“前置知识门槛”，即使代码很短。
23. 结果填空、交互、通信和输出答案必须考虑提交形式。
24. 卡常、压内存和语言差异必须考虑性能工程。
25. 应按赛时合理可想到的最简单正解评分。
26. 若只知道复杂官方解而不确定是否有简单解，应降低置信度。
27. 发现规律时必须进行防后见之明检查。
28. 多个高门槛只有彼此独立时才应用组合修正。
29. 理论正解难度与赛时通过难度应在数据特殊时分开说明。
30. CF 估分必须落在合法档位：800、900、…、3500、3500+。
31. `boxed / fbox` 风格用于强调最终结论，不能被普通标题或纯文本完全替代。
32. 结尾可有最终摘要，但开头总评才是主总评。
